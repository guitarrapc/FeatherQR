#enum DecodeStatus

public enum DecodeStatus : int

Result status of a decode attempt, shared by the Standard QR, Micro QR and rMQR decoders.

Success = 0,

Decoding succeeded.

InvalidMatrix = 1,

The input is not a valid module matrix (invalid size or no dark modules).

FormatInformationInvalid = 2,

Both format information copies are corrupted beyond BCH correction capacity.

DataUncorrectable = 3,

One or more Reed-Solomon blocks contain more errors than the ECC level can correct.

InvalidBitstream = 4,

The data bitstream is malformed (invalid segment values or truncated data).

UnsupportedContent = 5,

The bitstream is well-formed but uses a feature this decoder does not support (FNC1, Structured Append, or an unsupported ECI charset). A property of the symbol's structure, not of its text; see UnmappedCharacter for the per-character case.

DestinationTooSmall = 6,

The destination buffer is too small for the decoded text.

NotDetected = 7,

No symbol was detected in the image (finder patterns not found or inconsistent).

UnmappedCharacter = 8,

The symbol was read correctly, but one character has no mapping under the charset this decoder applies, so no text is produced.

Notes

Today this means a Kanji mode cell outside JIS X 0208 — in practice one of the 83 characters Microsoft CP932 adds in NEC row 13 (circled digits, roman numerals, unit ligatures). It is deliberately distinct from UnsupportedContent : that says the symbol uses a feature this library does not implement, and no reader choice changes it, whereas this says the symbol is well formed and a CP932-capable reader would read it. A caller that wants to fall back to such a reader should branch on exactly this status.

#enum EciMode

public enum EciMode : int

The character encoding declared in the symbol, as an ECI assignment.

Default = 0,

Picks the encoding from the content, which is what you want unless a reader demands otherwise.

Notes

Pure ASCII is sent with no ECI header at all, which is both smallest and most widely readable. Anything ISO-8859-1 can represent becomes Iso8859_1 , and the rest becomes Utf8 . The header is the whole cost, 12 bits in Standard QR and 11 in rMQR, and it is what can push the content into a larger version. Two characters in Byte mode at version 1-9, where the count indicator is 8 bits wide: "HE" no header 4 + 8 + 16 = 28 bits "Ca" ECI 3 12 + 4 + 8 + 16 = 40 bits "🎉" ECI 26 12 + 4 + 8 + 32 = 56 bits

Iso8859_1 = 3,

ISO-8859-1, covering ASCII plus Western European letters such as À, Ç, Ñ, é and ü.

Notes

The ECI header costs 12 bits in Standard QR and 11 in rMQR. Emoji, CJK and Cyrillic cannot be encoded; use Utf8 for those.

Utf8 = 26,

UTF-8, which covers every Unicode character: emoji, CJK, Cyrillic, Arabic, Hebrew and the rest.

Notes

The ECI header costs 12 bits in Standard QR and 11 in rMQR, and each character takes 1 to 4 bytes. For Western European text Iso8859_1 is denser.

#class MicroQRCodeDecoder

public static class MicroQRCodeDecoder

Micro QR code decoder based on ISO/IEC 18004. Decodes Micro QR module matrices back into text, including Reed-Solomon error correction.

Notes

Reads Numeric, Alphanumeric and Byte mode across M1 to M4, and Kanji in M3 and M4. Micro QR has no ECI, so a Byte segment is read as UTF-8 when the bytes are valid UTF-8, and as ISO-8859-1 otherwise. Kanji is mapped through JIS X 0208, so a cell outside that repertoire fails the whole Micro QR code with UnmappedCharacter rather than substituting a replacement character. Image scanning handles clean screen or scanner images, including rotation, mirroring, inverted colors, scaling and mild perspective. It is a separate entry point, and QRCodeDecoder keeps scanning Standard QR only.

#enum MicroQRSegmentation

public enum MicroQRSegmentation : int

How MicroQRCodeGenerator splits the content into encoding-mode segments. Micro QR capacities are tiny (5 digits at M1, 15 Byte-mode characters at M4-L), so mixing modes (for example a short prefix followed by a numeric tail) can drop the symbol a version, or encode content no single mode fits at all.

Single = 0,

One segment in the single mode that can represent the whole content (Numeric, else Alphanumeric, else Byte). The default, and the cheapest to encode.

Optimal = 1,

The mixed-mode split with the fewest total bits. Never selects a larger version than Single , emits the Single bit stream verbatim when a split would not shrink the symbol, and additionally encodes content that overflows every version in a single mode — unless the minimal-bit plan would be misread on decode (a relocated byte order mark, or a Latin-1 run the charset heuristic would read as UTF-8), in which case it reports "does not fit" rather than emitting a stream that decodes differently.

Notes

Opt-in because it prices candidate versions; the search allocates nothing (Micro QR content never exceeds 35 characters). The plan respects each version's mode set — M1 is Numeric-only and M2 has no Byte mode — so a version is never selected for a plan whose runs it cannot carry. Size buffers with the same segmentation you encode with, the two can select different versions.

#struct SymbolCorners

public readonly struct SymbolCorners : IEquatable<SymbolCorners>

Where a decoded symbol sits in the image: the four outer corners of its module area, quiet zone excluded, in the input image's continuous pixel coordinates (see ImagePoint ).

Notes

The corners are named in the symbol's own frame, not the image's: TopLeft is the corner beside the finder pattern that defines the symbol's top-left, wherever it landed in the picture. A rotated capture therefore reports rotated corners, and a mirrored capture reports them in reversed winding: seen on screen (y down), the corners of a symbol as printed run clockwise, and those of a mirrored capture run counter-clockwise. The four points form a general quadrilateral under perspective. They are estimates, and how tight depends on how much the decoder had to infer. At 8 pixels per module or more: Standard QR, fitted on three finders and an alignment pattern, holds every corner within half a module, flat, rotated, mirrored or keystoned. Micro QR and rMQR fit from a single finder and match that only flat and at right angles; an oblique rotation takes whichever axis angle still decodes and a keystone comes from a bounded search, so their far corners can be off by about a module, or a module and a half on an rMQR symbol foreshortened by 2 % or more. Two things loosen those figures. Below 8 pixels per module, read the bound in pixels: the corners are anchored on pattern centres that resolve to about a pixel at any module size, so the error stays near four pixels while the module shrinks under it (about 0.9 module at 3 pixels per module, on every symbology). And a Standard QR symbol whose bottom-right alignment pattern was not located — version 1 has none, and elsewhere a smudge over one module loses it — is fitted on the finders alone and held to about a module and a half, at any density. Error correction still reports Success , and nothing here says which fit ran. Populated only when the decode succeeded from an image. A matrix-level decode has no image and a failed image decode located nothing worth reporting; both leave the value at its default, which IsEmpty reports.

#class GradientOptions

public sealed class GradientOptions : IEquatable<GradientOptions>

Gradient configuration for symbol rendering.

Notes

Configures a linear gradient applied across the whole symbol, flowing in one of the directions of GradientDirection . For a simple two-colour gradient pass two colours; for more, add colours and optionally the stops they sit at. An instance is immutable through its API: the constructor copies the arrays it is given and no member hands one back, so a shared instance such as Default cannot be repainted by one caller for everyone else. A with expression varies the direction of an existing gradient — GradientOptions.Default with { Direction = GradientDirection.BottomToTop } — and the copy shares the colour array with the original, which is safe for the same reason: neither instance exposes it. Direction is the only init member, which is a rule rather than an omission: Colors and ColorPositions have to agree in length, and with sets one member at a time, so allowing with { Colors = … } would let a caller build a gradient whose stops no longer match its colours and only find out when it is drawn.
